# MICHI · Phase 17.5 product quality

**Beta decision: ready for a supervised playtest; physical-device sign-off is still open.** Comparisons below use screenshots from the running app. PDF pages are the visual references, not expected puzzle values or test data.

| Area | Change and evidence |
| --- | --- |
| Game and Coach | The running Coach had a conspicuous strip of unused paper between the board and sheet. The sheet now fills the space below the board, with its instruction at the top and actions at the bottom. Daily was played to completion on iOS: 57 player cells, one hint, no mistakes, and a Daily stamp. [Game, Coach Result and completion beside PDF pp. 45, 59 and 83](phase17_5_evidence/daily.jpg). |
| Home and Progress | The Daily mascot is anchored to the card edge, grows to the reference scale, and uses the happy variant for completion. Refresh retains the last Daily while loading. A player with no completed games or technique history sees the actual board-and-cat illustration extracted from PDF p. 81 and a first-puzzle action. Returning to Progress reloads local practice results. The walkthrough completed a Naked Single exercise with Coach assistance and then showed 8% mastery. [Lesson, Practice and Progress comparisons](phase17_5_evidence/learning.jpg). |
| Welcome and onboarding | The Welcome board now has the approved dotted coral path and full-size mascot (PDF p. 101). The first, second and fourth onboarding panels use their own approved artwork (pp. 28, 29 and 31); the technique cards remain native so their labels can be localized. [Running onboarding beside the PDF](phase17_5_evidence/onboarding.jpg). |
| Native identity | Replaced the template Flutter launcher icons with the grid and coral path used by the MICHI wordmark, on both platforms. |
| Motion and touch | Board changes blend the old and new painted states without duplicating the 81 interactive cells. Selected digits, notes, Coach instructions, Practice feedback, lesson steps, completion, mascot changes, tabs, Home cards and Scanner Review use short transitions. New animations honor Reduce Motion; fading instructions and review cells retain their current accessibility labels. Selection and notes use the lightest feedback; placement, mistakes and completion have distinct impacts. Haptic feel needs physical hardware. |
| Scan → Hint | Review offers **Continue in MICHI** and **I’m stuck — help me**. The latter checks conflicts and solution existence, asks HumanSolver for one deduction, and presents its structured four-stage Coach plan. Close returns to the same reviewed board. It does not create a game, overwrite progress, apply the move, or use the exact solution as a hint. Invalid, unsolvable, complete and unsupported positions receive distinct feedback. |
| Real newspaper | The original scan of Wicht/Hennebert training photo `image1.jpg` failed at grid detection: shadowed paper joined the grid border. A local-contrast fallback now requires repeated lines in both directions. In simulator Photos the same unmodified image reached Review: **81/81 values matched** ground truth, including one correctly recognized but low-confidence digit. Hint → Result → Close returned to Review; Continue in MICHI opened a normal imported game. On a second copy of the same photo, a legal 3 was added at row 9, column 4 before scanning. Review recognized the 3, the player confirmed a low-confidence 1, and Coach offered a single next placement of 4. Closing Coach preserved the external 3. These are regression cases, not a new accuracy estimate. [Source and license](../packages/sudoku_scanner/test/fixtures/newspaper/README.md). |
| Scanner discovery | Another puzzle now says that an external Sudoku can be scanned. The chooser names camera/photo input. Opening Scanner no longer prompts about replacing a game; that choice belongs to import. |
| Solving styles | Cell-first remains the default. Game input options offer number-first: arm a visibly highlighted digit and tap cells, including in pencil mode. Givens stay protected. Matching digits and matching pencil marks are highlighted. **Fill pencil notes** is explicit, computes legal candidates, and can be undone. Correct placements still remove peer notes; the app never fills all notes on its own. |
| Widget and App Intents | The iOS small Home Screen and rectangular Lock Screen widget show the local date and the actual Daily difficulty when available. Undated or stale difficulty is omitted. Only the date and difficulty enter the shared app group. The extension supports system tint and removable backgrounds. Its URL uses the same Daily flow, including resume and replacement confirmation. A cold tap on the pinned widget opened that day’s Advanced Sudoku in Game. [Widget, destination, scanned Coach and return to Review](phase17_5_evidence/native.jpg). Runner packages Scan, Continue and Today App Intents for Shortcuts. No Live Activity or Dynamic Island. |

**Walkthrough scope.** The four tabs and their return paths were exercised on the regular iPhone. Game and Coach were also checked on [iPhone SE in Ukrainian and Czech](phase17_5_evidence/compact.jpg) and [Pro Max in German](phase17_5_evidence/large.jpg). Account, onboarding, level selection, Profile, Settings, Week, paused Game, wrong entry, notes, unavailable hint, Why and empty Progress were also inspected on a simulator; account states were staged, not live provider sign-ins. An Android test emulator opened Daily and displayed Coach with Wi-Fi and mobile data disabled; both settings were restored afterward. The production entry point built for iOS Simulator and Android (debug); all four packages analyzed cleanly and all 401 workspace tests passed.

**Remaining differences and release checks.** Live content, greeting, dates, technique examples and mastery values are not reproduced from sample artwork. Guest Profile and Settings only offer features actually available; the PDF’s full settings list, badge history and illustrative streaks have not been faked. The native onboarding cards retain simpler diagrams than the PDF. The reference has no dedicated external-photo Coach screen; it reuses Game’s board and Coach. Verify camera capture under indoor lighting, physical haptic intensity, VoiceOver traversal, signed app-group provisioning, Lock Screen tint, and Siri invocation on an actual iPhone before wider beta. A simulator Photos selection cannot verify camera focus, glare, or shutter behavior.
